# 单目视觉远程推理跟踪抓取方案

## 目标和前提

目标是在没有深度相机的条件下，使用固定 RGB 摄像头观察桌面，通过远程 Ubuntu RTX 3070 完成目标识别、分割、跟踪和抓取候选推理，再由 Pi 上的 ROS 2、MoveIt 和 `ros2_control` 安全执行。

本文默认：

- 摄像头为固定 eye-to-hand 视角，能覆盖工作区、物体和夹爪。
- 场景以桌面物体和从上方抓取为第一阶段目标。
- RTX 3070 通常只有 8 GB 显存，模型必须分阶段运行，不能把所有大模型常驻显存。
- Foxglove 负责预览和诊断，不进入实时控制闭环。
- “SOTA”表示采用当前成熟的开放词汇、视频分割和基础模型组件，并通过本机数据实测选择，不表示未经验证地依赖单个排行榜模型。

## 核心判断：主几何不依赖单目深度网络

单目基础模型能输出很好的相对深度，但在新相机、新桌面和透明/反光物体上，绝对尺度和 Z 高度仍可能漂移。机械臂抓取不能直接把单目深度网络的数值当成安全位姿。

第一版采用更可控的度量方法：

1. 标定相机内参 `K`。
2. 使用 AprilTag 或 ChArUco 标定 `camera_link -> base_link` 外参。
3. 在 `base_link` 中标定桌面平面。
4. 将目标像素射线与桌面平面求交，得到可靠的度量 XY。
5. Z 使用桌面高度、物体类别高度先验和受控下降策略。
6. Depth Anything V2、UniDepth 或同类单目深度只用于物体前后关系、障碍排序和异常检测，不直接下发机械臂 Z。

若目标像素对应的是物体顶面而不是桌面，直接与桌面求交会因物体高度和相机倾角产生系统性 XY 偏差。已知物体应与其顶面高度对应的平面求交；未知物体在第一版只允许低矮目标，并把这部分偏差计入安全裕量和标定验收。相机尽量接近俯视安装也能减小该误差，但不能替代验证。

对于不规则堆叠、透明物体、未知高度和侧向抓取，单目方案不能提供与 RGB-D 等价的安全性。这些场景应增加深度相机、第二视角或末端力/触觉反馈。

## 总体架构

```text
Raspberry Pi 4B                              Ubuntu + RTX 3070

USB camera
  -> V4L2 native MJPEG
  -> latest-frame inference stream  -------> JPEG decode
  -> Foxglove preview                        Grounding DINO target acquisition
                                             SAM 2.1 mask tracking
                                             optional CoTracker3 validation
                                             2D grasp proposal/ranking
                                                    |
  <------------- pixel-space result + timestamp ----+
  -> stale/confidence/speed gate
  -> pixel ray + calibrated table intersection
  -> target pose in base_link
  -> MoveIt collision check and planning
  -> closed-loop visual correction
  -> ros2_control
  -> gripper result verification
```

远程主机只返回像素空间结果和模型置信度。相机标定、机械臂 TF、工作空间限制和安全决策保留在 Pi，避免远程模型或网络异常直接产生机械臂指令。

## SOTA 导向的模型组合

| 任务 | 首选候选 | 使用方式 | 3070 约束 |
| --- | --- | --- | --- |
| 开放词汇目标获取 | Grounding DINO | 根据文本提示在首次出现、丢失或低置信时运行 | 不逐帧运行，建议按需或 1-2 Hz |
| 目标掩码初始化与跟踪 | SAM 2.1 Hiera Small/Tiny | 首帧用检测框初始化，后续使用视频 memory 跟踪 | FP16，限制同时跟踪数量 |
| 遮挡和运动一致性 | CoTracker3，可选 | 跟踪目标内部点，检查 mask 是否漂移 | 只在疑似漂移或动态抓取时开启 |
| 2D 抓取候选 | Grasp-Anything++ 类模型或本项目微调网络 | 输出 `(u, v, angle, width, score)`，再做几何过滤 | 先离线比较精度和速度后选型 |
| 单目深度辅助 | Depth Anything V2 / UniDepth 类模型 | 只做排序、遮挡和异常检测 | 低频运行，不作为绝对 Z 真值 |

推荐的工程策略不是每帧运行全部模型，而是：

```text
Grounding DINO 低频获取目标
  -> SAM 2.1 高频跟踪 mask
  -> 目标稳定后运行抓取候选
  -> CoTracker/单目深度按异常触发
```

可用于基准评估的上游项目：

- [Grounding DINO](https://github.com/IDEA-Research/GroundingDINO)
- [SAM 2](https://github.com/facebookresearch/sam2)
- [CoTracker](https://github.com/facebookresearch/co-tracker)
- [Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2)
- [Grasp-Anything](https://github.com/airvlab/grasp-anything)

这些项目是候选组件，不应在没有本机延迟、显存和抓取成功率测试时直接宣布为最终依赖。

## 无深度的度量定位

像素点 `p = [u, v, 1]` 先通过相机内参得到相机坐标系射线：

```text
r_camera = inverse(K) * p
```

再使用标定外参将射线原点和方向转换到 `base_link`。若桌面平面为：

```text
n dot X + d = 0
```

射线 `X(lambda) = O + lambda * r` 与桌面的交点参数为：

```text
lambda = -(n dot O + d) / (n dot r)
```

目标 mask 的质心不能直接等同于最佳抓取点。需要综合：

- 2D 抓取网络给出的接触中心、角度和夹爪宽度。
- mask 边界与主方向。
- 夹爪在图像中的投影和遮挡。
- 投影到桌面后的物理夹爪宽度是否合法。
- 目标与工作区边缘、其他物体和机械臂底座的距离。

## 远程推理传输

Foxglove WebSocket 继续用于人类预览。远程推理建议使用独立链路：

```text
WireGuard/Tailscale secure network
  + Zenoh ROS 2 bridge or a bidirectional inference RPC
```

首选先评估 Zenoh，因为它能过滤 ROS 2 topic、跨网络工作，并保留现有消息模型。图像 QoS 使用 best-effort、depth 1 和 latest-frame；结果消息可以可靠传输，但 Pi 必须拒绝过期结果。

建议的数据接口：

```text
/vision/inference/image/compressed   sensor_msgs/CompressedImage
/vision/target_track                 zyarm_vision_msgs/TargetTrack
/vision/grasp_candidate              zyarm_vision_msgs/GraspCandidate
/vision/status                       diagnostic_msgs/DiagnosticArray
```

`TargetTrack` 至少包含：

```text
source_stamp
frame_sequence
track_id
label
confidence
mask_or_polygon
bbox
pixel_velocity
```

`GraspCandidate` 至少包含：

```text
source_stamp
track_id
center_u / center_v
angle
pixel_width
score
model_version
```

Pi 不接受只含 `x/y/z` 且没有源图时间戳、坐标系和置信度的远程结果。

## 抓取状态机

```text
IDLE
  -> ACQUIRE_TARGET
  -> TRACK_AND_STABILIZE
  -> COMPUTE_GRASP
  -> PLAN_PREGRASP
  -> VISUAL_CORRECTION
  -> CONTROLLED_DESCENT
  -> CLOSE_GRIPPER
  -> VERIFY_GRASP
  -> RETREAT
  -> PLACE or RECOVER
```

关键约束：

- 结果超过 200 ms、跟踪丢失或置信度低于阈值时不开始新动作。
- 机械臂运动期间持续检查 track ID，不能把新出现的物体误当原目标。
- 第一次规划只到目标上方安全高度，不直接下降抓取。
- 下降前重新观测并修正 XY 和角度。
- 下降速度和最大深度受限；夹爪闭合后根据位置、电流或视觉确认抓取结果。
- 任何网络断开只允许停止或撤退，不能沿用最后一个目标继续动作。

## RTX 3070 推理预算

建议初始输入为 `640x480`，视觉推理目标 10-15 Hz，摄像头和 Foxglove 预览保持 30 Hz。3070 8 GB 显存下：

- Grounding DINO 仅在获取和重获取目标时运行。
- SAM 2.1 使用 Small/Tiny checkpoint，并限制 memory 长度和目标数量。
- 抓取候选模型在目标稳定后运行，不与大检测模型同时占满显存。
- 使用 FP16；确认数值一致后再评估 TensorRT。
- 对每帧记录采集、发送、GPU 开始、GPU 完成、结果到达和控制采用时间戳。

延迟预算建议：

| 环节 | P95 目标 |
| --- | ---: |
| Pi 取帧到远程收到 | 40 ms |
| 稳态跟踪推理 | 70 ms |
| 结果返回 Pi | 30 ms |
| Pi 校验和坐标转换 | 10 ms |
| 总感知延迟 | 150 ms 以内 |

如果远程主机不在同一局域网，应先实测抖动。P95 无法稳定在 200 ms 内时，第一版只允许静止目标抓取。

## 分阶段实施

### 阶段 0：测量和安全基线

- 固定相机和线材，完成内参、外参和桌面平面标定。
- 打通 Pi 与 3070 的安全网络、时钟同步和 latest-frame 传输。
- 建立只观测不运动的延迟、掉帧和断线仪表盘。

### 阶段 1：已知标记静态抓取

- 使用 AprilTag/ArUco 代替神经网络目标。
- 验证像素到 `base_link` 的误差、MoveIt 预抓取和受控下降。
- 建立抓取状态机和所有停止条件。

### 阶段 2：开放词汇分割和跟踪

- Grounding DINO 初始化目标，SAM 2.1 保持 track ID。
- 只在 Foxglove 显示 mask、bbox、轨迹和置信度，不驱动机械臂。
- 收集遮挡、反光、重复物体和快速运动失败样本。

### 阶段 3：静止物体抓取

- 接入 2D 抓取候选和 mask 几何过滤。
- 先抓取高度已知、形状规则、彼此分开的物体。
- 加入抓取结果验证和失败恢复。

### 阶段 4：慢速移动物体

- 使用带时间戳的像素速度和 Kalman/EKF 预测补偿远程延迟。
- 限制目标速度和允许抓取区域。
- 规划、视觉修正和下降期间持续验证目标身份。

### 阶段 5：扩展场景

- 堆叠、未知高度和严重遮挡先增加第二视角或深度/触觉，再扩展抓取策略。
- 使用本机失败数据微调检测、分割和抓取候选模型。

## 验收指标

第一阶段建议以这些门槛决定是否允许真机自动抓取：

| 指标 | 建议门槛 |
| --- | ---: |
| 标定重投影误差 | 小于 1 px |
| 桌面 XY 定位 P95 | 小于 5 mm |
| 稳态跟踪更新率 | 至少 10 Hz |
| 感知端到端延迟 P95 | 小于 150 ms，同局域网 |
| 静止规则物体抓取成功率 | 至少 90%，50 次测试 |
| 断网/过期结果继续运动次数 | 0 |
| track ID 错换后继续抓取次数 | 0 |

## 推荐的首个实现切片

第一版只做：固定桌面、一个文本指定目标、静止物体、从上方抓取。技术组合为：

```text
V4L2 native MJPEG
  -> remote Grounding DINO acquisition
  -> SAM 2.1 tracking
  -> mask PCA + simple 2D grasp baseline
  -> calibrated table intersection on Pi
  -> MoveIt pregrasp
  -> one visual correction
  -> limited descent and gripper verification
```

这个切片能先验证远程推理、无深度几何和安全闭环。完成后再决定是否引入 Grasp-Anything++、CoTracker3、单目深度或更复杂的 VLA 模型。
